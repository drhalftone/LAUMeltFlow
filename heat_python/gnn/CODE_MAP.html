heat_python / gnn

Surrogate Code Map

How the GNN surrogate is put together, which file does what, and the exact lines to open when you want to change something.

01The whole thing in one paragraph

The solver runs the real physics and records what happened. Those recordings become training pairs of the form state now and state one super-step later. A small neural network learns to make that jump. At evaluation the network is fed its own output over and over, and the result is compared against the solver.

A super-step is the surrogate's time step. It is roughly 200 times larger than the solver's, and that ratio is where the speedup comes from.

Two folders, and the split is meaningful. heat_python/ is the Fortran port, ported physics only, no machine learning anywhere in it. heat_python/gnn/ is the surrogate.

03What the data actually is

Two objects matter, and confusing them will cost you an afternoon.

A trajectory

One solver run, recorded. Arrays of shape (S, m) where S is the number of snapshots and m is the number of cells including the two ghost cells. Built by data_gen.py:34, loaded by data_gen.py:59.

The ghost cells matter enormously. They are the two fake cells outside the domain that carry the boundary condition. Keeping them in the recording is what lets the surrogate be told what the boundary is doing at every step instead of having to guess.

Node features

Every cell becomes a row of numbers. Built at graph.py:50:

65feats = [T[:, :, None], rho[:, :, None]]
66feats += [rho_i[:, k, :, None] for k in range(ns)]
67feats.append(por[:, :, None])
68names = ["T", "rho"] + [f"rho_i{k}" ...] + ["porosity"]
69
70# gas runs append two more columns
73names += ["pg", "mdotf"]

So a cell is [T, rho, rho_i0, rho_i1, rho_i2, porosity, pg, mdotf], eight numbers for the gas case. Note the gas columns are appended at the end deliberately, so the gas off layout is a prefix of the gas on layout and the same code handles both.

Edges are relative, not absolute

An edge stores the neighbor minus me, plus the spacing. Not the neighbor's absolute state. That mirrors the physics, since conduction is driven by a difference across a face. You can see it built identically in three places, which is itself worth knowing: gnn_model.py:122, gnn_flux_model.py:126, train_rollout.py:59.

04The model, four layers deep

Each class inherits from the one above and overrides forward. Reading them top to bottom is reading the project's history in order.

The forward pass, the twenty lines that matter

gnn_flux_model.py:302. Everything else in the project exists to feed this function or to measure it.

306h_self  = self.node_encoder(node_feat)      # encode me
307h_left  = self.node_encoder(nbr_l)          # encode left neighbor
308h_right = self.node_encoder(nbr_r)          # encode right neighbor
312s_self  = node_feat[..., self.out_in_cols]
314flux_left  = self._conductance(...) * (s_self - nbr_l[...])
316flux_right = self._conductance(...) * (s_self - nbr_r[...])
322source = self._pyro_source(node_feat)       # chemistry
324return -(flux_right + flux_left) + source

Read the last line as a balance sheet. What I lose across my two faces, plus what is created inside me. That is the finite volume statement, expressed as a neural network.

The one trick that makes it stable

gnn_flux_model.py:290. The conductance is squeezed into a bounded range:

296D = self.face_cap * torch.sigmoid(self.cond_logit)  # face_cap = 0.5

sigmoid returns something between 0 and 1, so D lands between 0 and 0.5. With two neighbors the weights sum to at most 1. Expand the algebra and the update becomes

T_new = (1 - D_l - D_r) * T_self  +  D_l * T_left  +  D_r * T_right

Every coefficient is positive and they sum to one, so the result is a weighted average. It physically cannot land outside the range of the three inputs. That is why this model stayed bounded where the free flux version reached 100,000 K.

The torch.no_grad() wrapped around the kinetics at gnn_flux_model.py:270 is not cosmetic. The W^(1-psi) term has exploding gradients for nearly charred cells and produced NaNs during training. Since those kinetics contain no trainable parameters, blocking the gradient costs nothing and fixes it.

05Training

The trainer is train_rollout.py, and the interesting part is that it does not train on single steps. It unrolls several steps and puts the loss on the whole short rollout.

The inner loop is train_rollout.py:229:

229for k in range(M):                 # M super-steps of unroll
230    truth_k = seqs_t[bt, bs_ + k]  # ghosts = the true forcing
233    for _ in range(args.substeps): # each super-step = 8 sub-steps
234        interior = mesh_step(model, state, dx_t, stats, consts, cols)
238        state = torch.cat([truth_k[:, 0:1], interior,
239                           truth_k[:, m-1:m]], dim=1)
241    err = (state[...] - truth_next[...]) / node_std_out
261    loss = loss + se.mean()

Three things are happening. The ghost cells are re written from truth every step, so the model is always told the correct boundary condition rather than having to predict it. Each data step is taken as eight smaller sub steps, because one bounded update only reaches the immediate neighbor and the heat needs to travel further than that. And the loss accumulates across the unroll, which is what teaches the model to be stable rather than merely accurate once.

Loss weighting

Two optional weights, both at train_rollout.py:244. --loss-weight upweights hot cells, spatially. --temporal-weight upweights cells that are changing fast, which is the sharp flux transient. The temporal one is the transfer learning idea from the Cao paper, applied as a loss weight instead of staged layer freezing.

06Evaluation

eval_rollout_traj.py:76. This is the honest test, because the model is fed its own output and never sees the truth again except for the boundary.

76for k in range(S - 1):
77    state[0] = gt[k, 0]              # ghosts from truth
80    for _ in range(substeps):
81        new_int = model.step_mesh(state, dx, out_idx)
91        state[1:m-1] = new_int       # ghosts untouched

Compare this to the training loop above. Same shape, but nothing corrects the interior. Errors compound, which is exactly what you want to measure.

07Landmines

Four things in this codebase that will waste your time if nobody warns you.

Naming collision

step_mesh and mesh_step are two different functions that do the same job. gnn_flux_model.py:113 is the inference version, wrapped in @torch.no_grad() and using in place edits. train_rollout.py:39 is the training version, written without in place edits so gradients can flow backward through it. They must stay in sync, and nothing enforces that.

The scaling bug that cost a session

train_rollout.py:133. The conductance flux works on differences normalized by the absolute state spread, but the output was being denormalized by the per step delta spread, which is around fifty times smaller. Effective diffusion was throttled about thirtyfold and the thermal front could not penetrate no matter what value D took. The fix is three lines:

133if args.conductance:
140    stats[5] = node_std_out.clone()

The symptom looked like a physics problem, a frozen front, and several hours went into chasing physics before the cause turned out to be one wrong variable of the right shape.

train_gnn.py looks dead but is not

It appears fully superseded by train_rollout.py, and almost is. But train_rollout.py:34 imports select_out_cols from it. Delete it and the live trainer breaks.

Checkpoints carry their own configuration

Training saves state_dict plus every architectural choice, at train_rollout.py:279. Evaluation reads those back and rebuilds the right class automatically. This is why you do not pass architecture flags to the evaluator, and why moving files between folders did not break any existing model file.

09Running it

Every command gained a gnn segment in the August 2026 reorganization. Solver side commands did not change.

# build the dataset
python -m heat_python.gnn.make_aw2_fine --n 24 --record-every 200 ...

# train the headline model
python -m heat_python.gnn.train_rollout \
    --data aw2_fine_dataset_n24.npz --conductance --physical-source \
    --real-kinetics --fixed-cond 0.375,0,0,0.3,0.3 --uniform-cond \
    --temporal-weight 8 --substeps 8 --rollout-steps 2 ...

# evaluate
python -m heat_python.gnn.eval_rollout_traj --traj aw2_holdout_fine.npz --model ...

# the solver itself, unchanged
python -m heat_python.solver --case-dir .../aw2_tc21 --gas
