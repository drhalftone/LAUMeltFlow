What the model is

The surrogate holds 110,299 parameters. Encoders, message-passing layers, layer norms, output heads. The usual apparatus.

In the configuration that produced the headline result, ten of them train. The rest never receive a gradient.

Normalizing

Raw values span 0.0147 to 101,524. A network cannot train on that spread. Each feature becomes standard deviations from its mean, using statistics stored inside the checkpoint.

raw   [ 1339.88   224.25    28.00   614.49  1600.00     0.85  101524.25    0.0147 ]
mean  [  482.53   270.45   242.68   861.86  1600.00     0.81  101732.10    0.0010 ]
std   [  260.51    19.12   104.62    92.41     0.00     0.02     286.67    0.0020 ]
                              (raw - mean) / std
norm  [    3.291   -2.417   -2.052   -2.677     0.000     2.417      -0.725    7.911 ]

Temperature reads 3.291, meaning this cell sits 3.3 standard deviations above the domain average. That is what "near the hot surface" looks like numerically. The inert species has zero standard deviation and normalizes to zero, correctly contributing nothing.

Forward

The network predicts a change, not a state. It outputs in normalized units, then multiplies by the stored scale to reach kelvin.

network output      0.000832
x y_std (260.51)    0.2169 K   predicted change
solver truth        0.4846 K   what actually happened

predicted T_new     1340.0980
true      T_new     1340.3657
                    ---------
miss                0.2677 K

It under-predicts by about a quarter kelvin on a step where the true change is half a kelvin. On a field spanning 300 to 1600 K, that is a small error in a difficult place.

Loss

The error is divided by the same standard deviation before squaring, so every channel contributes on comparable footing rather than temperature drowning out porosity.

error         (1340.0980 - 1340.3657) / 260.51  =  -1.0276e-03
loss = error^2                                    1.0560e-06

Squaring makes the loss positive and penalizes large misses disproportionately. This single number is what gets differentiated.

Backward

One call to loss.backward(). Automatic differentiation walks the computation in reverse, asking of every parameter: if this number rose slightly, would the loss rise or fall?

Here is the entire answer.

d(loss)/d(cond_logit)   [ -5.849e-07   0   0   0   0 ]
d(loss)/d(pyro_coef)    [ -7.343e-07   0   0   0   0 ]

every other parameter   no gradient
global gradient norm    9.387e-07

Both gradients are negative, meaning the loss falls if these values rise. The model under-predicted, so the correction points upward. Only the temperature channel is active, since the char channels have their conductance pinned near zero and the inert channel has no dynamics.

Why the encoders get nothing

With --uniform-cond, conductance comes from a single learned scalar per channel rather than from a network reading the cell state. The node encoder, geometry encoder, flux MLP, and conductance MLP are all bypassed. They exist because the class inherits them, but no path connects them to the loss. They are structurally dead in this configuration.

The update

Subtract the gradient, scaled by the learning rate. That is the whole of gradient descent.

new = old - lr x gradient

cond_logit[0]  0.713174 - 3e-04 x (-5.849e-07)  =  0.713174
                                                  change: +1.75e-10

D = 0.5 x sigmoid(cond_logit)
               0.335551  ->  0.335551

The step is invisible at six decimals. That is not a failure. This model is converged, and one cell from one snapshot should barely move it. Training took tens of thousands of steps like this one, on batches of hundreds of cells.

Part two

Why the physics carries the model

Ten trainable numbers reproduce a coupled multiphysics solver to 18 K. That only works because nearly everything the model does is not learned.

ComponentWhere it comes fromStatus
Arrhenius pyrolysisThe solver's own kinetics, transcribedFixed
Bounded-average updateStructural, from the finite-volume formFixed
Conduction rate DMeasured, then relaxed around that anchorLearned, 5
Gas couplingLearned from dataLearned, 5

The Arrhenius law runs under torch.no_grad(). It holds no trainable parameters and executes exactly as the reference solver executes it, using the real A, E, and psi values from the material file.

The anchor, visible in the numbers

At initialization cond_logit is set so the conductance lands precisely on the measured physical value. Training may move it, but it starts there.

at init      cond_logit = [ 1.0986, -9.2102, -9.2102,  0.4055,  0.4055 ]
             D          = [ 0.3750,  0.0000,  0.0000,  0.3000,  0.3000 ]
                          exactly the measured diffusion number

after train  D          = [ 0.3356,  0.0000,  0.0001,  0.2540,  0.2576 ]
                          moved 10.5 percent, stayed near the anchor

This is the inverse step. The field is fixed and the parameter is freed, and training recovers an effective rate close to the measured one. Proximity to the anchor is evidence the model is well posed, not evidence it discovered a new physical constant.

The evidence

The argument for structuring physics in is not theoretical here. Four models, same data, same network, same held-out test.

The part that matters

The purely learned model is not slightly worse. It reaches 100,000 K while the solver stays under 1700 K. More data does not fix it. More capacity does not fix it. Structuring the known physics into the update does.

Saying it in one sentence

A stiff coupled problem does not carry enough information in short rollouts to learn conduction and chemistry from scratch, so you supply them and let the network learn only what remains.

The honest caveat

This is not a physics-preserving surrogate. It gives up the solver's exact energy conservation, because it never forms an energy variable at all. What it keeps is a different guarantee: every update is a weighted average of a cell and its neighbors, so the field cannot exceed its surroundings. That is why it stays bounded where the free model did not.
